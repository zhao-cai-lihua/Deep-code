# Deep Code v0.6.3 cumulative final review

Date: 2026-09-09

Branch: `codex/v0.6.3-evidence-safety`

Fixed point: `v0.6.2` / `889a57981d7478f24f9e52a02b63eb6625bd8a98`

## Scope and method

This review compares the complete v0.6.3 candidate line with the fixed v0.6.2 release, rather than reviewing only the latest patch. The Spec axis is the user-approved v0.6.3 Engine Trust and v0.7.0 Evidence Gate plan. The Standards axis is `AGENTS.md`, `docs/CONTEXT.md`, `docs/ARCHITECTURE.md`, the current handoff, and the executable implementation.

The audit started from actual Main, Preload, Renderer, Adapter, Store, Runtime Supervisor, projection, and test code. Documentation and source-string tests were not accepted as runtime evidence.

## Outcome

No unresolved P0 or P1 issue remains in the reviewed source. Harness is still the only Session, model, tool, permission, and execution truth; no second Agent Loop was introduced. Four P1 gaps found during the cumulative pass were fixed before rc.5:

1. **Exact prompt admission correlation.** A newly admitted request could previously project an older completed Turn before its own durable user message arrived. Deep Code now carries the request JSON-RPC id returned by its Adapter boundary, matches it to `user/message.source.rpcId`, and opens only that Turn's window. Missing durable evidence stays `queued`.
2. **Direct task-selection race.** Task clicks, new-task creation, and workspace switching could allow an older asynchronous Workbench result to replace a newer selection. All direct selection paths now share the monotonic generation plus `{taskId, sessionId}` gate.
3. **Pre-prompt target race.** A task could change while asynchronous model-route preparation was in progress. Main now revalidates the current task and Session immediately before `session.prompt` as well as at entry.
4. **Timeout cancellation wording.** Acceptance of `session.cancel` was being described as if the Turn had already stopped. The projection now distinguishes “stop request accepted” from a terminal event and keeps Engine state unknown until terminal evidence exists.

## Standards axis

- High-risk semantics are behind small behavior-tested modules: Engine trust, TaskRunSnapshot, task lifecycle, refresh gating, send-target validation, timeout projection, immutable task storage, and Memory Vault rules.
- Main and Renderer remain broad orchestration files. `src/main.cjs` and `src/renderer/shell.js` should be decomposed after stable release, but a broad refactor now would increase release risk without changing the trust contract.
- Some static source assertions remain appropriate for CSP and forbidden API reachability. Lifecycle, evidence, permissions, routing, recovery, and task identity must continue to use behavior tests.
- Architecture documentation was corrected in rc.5: ecosystem discovery is read-only, and a five-minute wait proves only that a cancellation request was sent until Harness supplies terminal evidence.

## Spec axis

- Managed/shared Engine admission, compatibility allowlisting, shared-Engine confirmation, random managed ports, environment filtering, pinned installation source, read-only ecosystem discovery, Memory quarantine, secret rejection, single-instance ownership, immutable task snapshots, strict Session event filtering, same-Turn evidence, stop-and-delete, and generation-gated refresh are present.
- `TaskRunSnapshot` no longer combines old route/terminal evidence with a new admission. It consumes the exact durable Turn associated with the locally generated prompt RPC id.
- Permissions and confirmed file changes remain structure-derived. Text that merely mentions a permission, tool, command, or success does not become a trusted work receipt.
- A request being accepted, a cancel being accepted, a command exiting successfully, and a Turn reaching terminal state remain distinct claims.

## Verification completed

- Focused red/green behavior tests were added for every rc.5 correction.
- Full `npm test`: **251 passed, 0 failed**.
- `git diff --check`: passed; displayed line-ending notices are the repository's Windows conversion warning, not whitespace errors.
- The standard rc.5 Windows portable packaging command completed successfully. An earlier rc.4 output-name lock was bypassed without stopping the user's running process; the final rc.5 artifact itself was not locked.
- Packaged `app.asar` contains the new prompt-admission, refresh-gate, target-guard, and timeout-projection code.
- No Provider call, API Key read/write, task deletion, workspace modification, or user-process termination was used for this review.

## Not yet proven

- The final rc.5 UI interaction matrix still requires human acceptance in the packaged app.
- No real Provider call was repeated, because it would add cost without improving evidence for these local projection/race fixes.
- A successful build proves packaging and inclusion, not the final GitHub release assets; the release workflow must still pass after tagging.
- v0.6.3 is not stable until the bounded rc.5 checks in `docs/HANDOFF_CURRENT.md` pass.

## Release decision

Publish rc.5 as a prerelease. Do not add UI modules, model automation, prompt-injected Memory, personality-card behavior, or ecosystem execution before stable v0.6.3. After acceptance, merge and publish the stable tag from the reviewed commit, then continue Evidence Gate work only from observed upstream event gaps.
