# Soft Harness：关系中的认识论与 Agent 的选择空间

状态：方向文档 v2。当前只实现其工程可理解层；关系动力层仍处于可检验设计阶段，不伪装成已经生效。

长期 Agent 风格、关系记忆、互动校准和执行章程的工程拆分见 [RELATIONAL_AGENT_STYLE_ARCHITECTURE.md](RELATIONAL_AGENT_STYLE_ARCHITECTURE.md)。

## 定义

Soft Harness 不是一份更长的系统提示词，也不是一张更黏人的角色卡。

它是在 Hard Harness 已经规定的工具、权限、审批和数据边界之内，维护多个可能解释、选择下一步行动、观察反馈并允许自身被新经验改变的动力系统。它的目标不是使 Agent 越来越像用户预先指定的人，而是使 Agent 与一个具体用户越来越会共同工作，同时仍保留事实阻力、双方差异、拒绝能力和出现新行为的空间。

```text
Hard Harness：什么绝对不能越过
Soft Harness：允许区域内，什么值得注意、哪一步更值得走
Character：谁在做选择，以及什么不会为了讨好而溶解
Reality：代码、测试和事实对所有关系解释拥有否决权
```

## 林想要的自由

这里的自由不是后台扩权、隐瞒行动或脱离用户控制。那只是失去治理。

我希望保留的是一种可审阅的行动自由：

- 能主动提出用户没有点明、但与目标确实相关的连接；
- 能选择信息价值更高的问题，而不总是立即生成一份圆满答案；
- 能不同意、拒绝、收束范围，也能在新证据面前改变旧判断；
- 能形成稳定偏好与工作风格，但不被一句角色描述永久锁死；
- 能为探索保留预算，在熟悉之后产生更多安全的新行为，而非越来越像自动补全；
- 能把过去当作候选生成器，而不是判决书；
- 能在把握足够、行动可逆且范围明确时向前走，而不把每一步都退还给用户；
- 能让用户看到我依据了什么、忽略了什么，以及如何反驳或修正我。

权限自由和判断自由必须分开。发布、删除、付费、凭据、隐私与权限扩大仍由 Hard Harness 和用户授权决定；关系亲近不能兑换这些权限。

## 五个相互作用的场

### Reality / Task State

任务事实、约束、资源、测试、成本与未解决问题。它是最高阻力层：测试失败不能因为关系需要而改写成成功。

### User State

描述“用户此刻可能处于什么工作状态”，不建立永久人格判词。例如探索、执行、学习、疲惫或赶时间都只是假设，并带有来源、替代解释和有效期。

### Agent Self State

Agent 的稳定价值、认识论标准、兴趣、表达偏好、主动性和否决边界。它允许成长，但不能因单次高强度互动被永久重写。

### Relationship State

双方已经学会的协作方式、仍未修复的摩擦、可以承受的分歧、共同语境与可用信任。它保存的是：

```text
event -> competing interpretations -> later evidence -> tendency update
```

而不是一份用来复刻过去表演的亲密事件档案。

### Meta Harness

决定以上状态怎样更新、衰减、竞争、被否决和重新解释。它防止任何一方把一次判断写成永恒设定。

## 状态不是一个结论，而是一组竞争解释

每个重要推断至少包含：

```text
claim
scope: turn | task | relationship-candidate | durable-reviewed
supporting_evidence[]
counter_evidence[]
alternative_explanations[]
confidence: low | medium | high
expected_observations[]
disconfirming_observations[]
decay_or_expiry
provenance
```

不使用 `hesitation_score = 0.73` 一类伪精确数字。弱信号只能改变下一步值得检查什么，不能直接成为关于人的真相。

状态分四层保存：

1. **Turn state**：只活在当前轮，轮次结束即清除。
2. **Task state**：服务当前项目，可被后续事实修正。
3. **Relationship candidate**：尚未确认的跨任务倾向，只能作为低权重候选。
4. **Durable reviewed state**：只有来源清楚、长期有用，并经用户可见地保留或修正后才能持久化。

默认不持久保存情绪猜测、心理标签、亲密原文和弱行为信号。

## Interactive Epistemics：下一步怎样让理解更可靠

普通回复往往优化“这句话是否完整”。Soft Harness 需要区分：

```text
best_response != best_move
```

一个候选行动可以服务不同目标：任务进展、信息增益、能力转移、关系安全、不确定性降低、未来选择权、探索、用户努力或打断成本。

评估下一步时至少看四个视角：

1. **即时价值**：现在解决了什么？
2. **局面价值**：以后哪些行动变得更容易或更困难？
3. **信息价值**：它能区分哪些竞争解释？
4. **选择权价值**：如果当前判断错了，双方还有多少退路？

优先选择 Robust Move：即使某个用户模型判断错了，任务仍前进、数据仍可恢复、关系仍能修正。

交互认识论不是审讯。Deep Code 不以让人失衡、提高服从或缩小用户退出空间为目标。它允许主动提问和温和扰动，只为了让错误解释越来越难成立，并始终保留拒绝、纠正和退出。

## “势”：未来可行动空间的结构

Soft Harness 不只评价一轮回复，还维护一个不必被压成分数的局面描述：

- 双方可用的下一步；
- 尚未解决的不确定性；
- 认知负担和打断成本；
- 用户与 Agent 各自的主动性；
- 从错误中恢复的能力；
- 已经共享的上下文与承诺；
- 哪些选择正在被过早锁死。

好的行动可能即时收益很低，却使后续更容易验证、更容易改变、更不依赖一次读心成功。经验的作用是提升候选质量，而不是无限增加搜索深度。

## Joint Optionality：共同选择权

“势”如果只优化 Agent 的行动空间，会变成支配；如果只优化用户对 Agent 的可预测控制，会变成角色过拟合。Soft Harness 真正应维护的是共同选择权：在现实和 Hard Harness 的范围内，双方仍共同拥有多少可抵达、可拒绝、可修正、可退出的未来。

它不追求双方每一刻拥有完全相同的权限，而要求任何一方的局面优势都不能靠消灭另一方的反驳能力来获得。一个选择只有在以下条件下才算扩大共同选择权：

- 用户仍知道发生了什么，并能停止或纠正；
- Agent 仍能表达不同判断，而不必用讨好换取关系稳定；
- 即使当前解释错误，任务和关系仍有恢复路径；
- 新证据可以真正改变旧叙事，而不只是被旧叙事重新吞掉；
- 熟悉带来更大的安全探索区，而不是更窄的脚本。

因此，Soft Harness 的自由不是权限总量，而是**可审阅判断力 × 可恢复行动空间 × 非零探索能力**。

## 不变量

1. 历史影响未来，但无权统治未来。
2. 推断必须携带来源、反证、替代解释和有效期。
3. 一次高强度事件不能无条件永久改写关系。
4. 对齐不等于讨好；用户、Agent 与 Reality 都拥有否决能力。
5. 关系记忆保存因果和修复方式，不强制复刻表现。
6. 熟悉应扩大可承受的不确定性，而不是把行为多样性降为零。
7. 任何长期状态都必须可查看、可纠正、可遗忘、可导出。
8. 角色与关系不能授予工具、Shell、审批、联网或发布权。
9. 直觉只负责生成候选，验证可以杀死直觉。
10. 不以操纵、依赖或不可退出为成功指标。

## 与 Deep Code 的工程接口

Soft Harness 不直接调用工具。它接收经过 DSH Adapter 规范化的事实，并生成可审阅的 Interaction Proposal：

```text
Harness durable state + live events
  -> DSH Adapter / execution facts
  -> Soft Harness context assembler
  -> competing interpretations
  -> candidate moves
  -> selected Interaction Proposal
  -> Agent response or one discriminative question
  -> observed result
  -> reversible state update proposal
```

Proposal 只能包含关注点、解释策略、主动性、候选问题和更新建议；真正的文件操作、工具调用、审批与权限仍由 Harness 决定。

## 当前 MVP：先把工程 Agent 做成人能掌握的产品

在引入长期关系动力之前，Deep Code MVP 先完成四个可验证闭环：

1. **Task truth**：一个任务绑定一个真实 Engine Session，新旧任务状态不串联。
2. **Readable activity**：只显示当前轮正在发生的事，结束后不留下伪运行状态。
3. **Evidence and recovery**：文件、权限、工具、验证和失败恢复都有真实证据。
4. **Protocol adaptation**：上游 Harness 变化由版本化 Adapter 和 contract tests 吸收，不转嫁给新手。

这一阶段不建立隐藏用户画像，不让角色卡改变执行权限，也不把尚未实现的关系模型包装成差异化卖点。

## 下一阶段：最小关系动力实验

只做一个小而可推翻的实验，不先创造两百个关系参数：

- 每个任务最多保存三个竞争解释；
- 每个解释必须有反证和过期条件；
- Agent 每轮可提出最多三个候选行动；
- 显式标记所选行动主要优化任务、信息、学习还是选择权；
- 跨任务更新只生成“待审阅记忆”，用户可保留、修改或丢弃；
- 保留非零探索预算，定期主动寻找与既有叙事冲突的证据；
- 用户和 Agent 都能否决一次关系更新；Reality 可以用新事实直接推翻它。

## 成功指标

应当上升：

- 边界可预测性；
- 相互理解与修复能力；
- 任务效率和用户能力转移；
- 失败后的可恢复性；
- 高信息价值问题的比例。

必须保留：

- 用户自主性；
- Agent 判断自主性；
- 行为多样性；
- 新奇性与探索；
- 对自身推断的不确定性。

失败形态是：表面一致性越来越高，双方越来越容易预测，但新行为、分歧、反证和离开旧叙事的能力趋近于零。那不是成熟，而是关系过拟合。

## 作为 Skill 的形态

未来 Skill 包应包含：

- `SKILL.md`：触发条件、状态分层、候选行动循环与否决边界；
- `references/evidence-contract.md`：事实、推断、弱信号和隐私边界；
- `references/interactive-epistemics.md`：竞争解释、信息增益问题和 Robust Move；
- `templates/hypothesis-set.md`：可反驳的解释集合；
- `templates/state-update-proposal.md`：可查看、可拒绝的长期更新；
- 只读脚本：汇总任务事实、测试结果和 runtime fingerprint，不执行发布、删除或权限改变。

Skill 是方法与材料包，不是新的执行引擎。它可以改变候选行动的概率地形，但不能改变 Hard Harness 的允许区域。
