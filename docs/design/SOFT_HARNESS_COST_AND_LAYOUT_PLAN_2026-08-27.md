# Soft Harness、费用与工作台布局计划（2026-08-27）

## 决策摘要

Deep code 的下一阶段不再增加一批并列卡片，而是收敛成三个稳定表面：

1. **左侧导航**：只保留新任务、任务、工作区、项目与 Skills、生态发现和设置。
2. **中央对话**：只保留人的请求、Agent 的最终答复、Decision Gate、Outcome 和 Recovery；中间思考与工具过程默认折叠为一个可展开的“过程”。
3. **右侧检查器**：可折叠地承载当前运行、证据、用量与任务属性；窄窗口时变成抽屉，不挤压对话。

这不是一次纯视觉改版。每个表面只消费 DSH Adapter 投影出来的事实，不建立第二套任务、权限、费用或执行状态。

## P0：本轮已完成的可靠性闭环

- Decision Gate 提交时先暂停空闲计时，避免“提交请求正在路上，五分钟计时器先取消任务”的竞态。
- 选项、文本和输入法产生的每次 `input` / `change` 活动都在本地重置五分钟空闲窗口；该动作不调用模型，不消耗 token。
- Harness 返回 `not-pending` 或 `bad-response` 时保留具体原因，并在对话中显示“原因 / 安全说明 / 下一步”，不再只显示“没有确认”。
- 对话输入区提供停止按钮，调用现有 Harness 取消路径；停止后进入可恢复的 interrupted 状态。

## P1：对话过程折叠

### 普通视图

每一轮只显示：

- 用户消息；
- 一个折叠的过程行，例如“过程 · 12 步 · 4 次工具调用 · 48 秒”；
- 最终答复；
- Outcome / Recovery（存在时）。

过程行展开后才显示 Skill、Think 摘要、Glob、Read、Shell、Web 等事件。不得展示或声称展示模型私有思维链；这里只呈现 Harness 已公开的过程摘要和工具事实。

### 实现约束

- 先在 DSH Adapter 中保留 Turn / Step / message-kind / terminal 边界，再做折叠；不能依靠英语开头、消息长度或 DOM 顺序猜“哪一段是最终回答”。
- 折叠状态属于当前任务、当前 Turn，不能跨任务串联。
- 失败工具、Decision Gate 和权限请求即使过程折叠，也必须保留可见提示。

## P1：右侧检查器

左侧红圈中的“本轮状态”移入右侧检查器，并分成四个可独立折叠的段：

1. 当前运行：阶段、实际模型、排队项、停止。
2. 结果与恢复：Outcome、Recovery、需要用户做的下一步。
3. 证据：改动文件、测试、构建、失败工具、官方轨迹入口。
4. 用量：本轮与本任务累计 token、上下文占用和费用估算来源。

桌面宽屏默认展开“当前运行”，其余折叠；用户折叠偏好全局保存，但各任务的内容与内部展开状态隔离。窄窗口改为右侧抽屉。左栏因此只承担导航，不再同时承担监控仪表盘。

## 用量与费用事实模型

### 第一阶段：只显示事实

DSH Adapter 应等待上游稳定提供并保存以下数据：

- 实际 provider 与 model；
- 本轮 input、cached input、output、reasoning output（上游存在时）；
- 本任务累计 token；
- 可选的 context window 与占用比例；
- 数据来源和更新时间。

Harness 没有提供时继续明确显示“当前 Engine 未提供用量”，不能按文字长度估算成事实。

### 第二阶段：可关闭的金额估算

货币金额不是 token usage 本身。只有同时知道实际 provider、实际模型、计费身份、缓存规则、费率快照日期和币种时，才显示“估算 ¥x.xx”，并允许用户关闭。订阅、赠送额度、第三方代理价和企业合同可能使估算不等于真实账单。

费用视图建议同时显示：

- 本轮：事实 token + 可选估算金额；
- 本任务：累计事实 token + 可选估算金额；
- 成本来源：模型推理、额外模型调用；
- 零模型费用动作：启动 Engine、浏览本地任务、输入续时、查看生态目录、展开证据。

不把不同 provider 的 token 直接相加成一个“额度百分比”。

### 预算保护

- 用户可设置提醒阈值；达到阈值时在下一轮前提醒。
- 可设置“完成当前安全步骤后停止”，但不在文件写入到一半时粗暴杀进程。
- 每一个会新增模型请求的功能必须显式记为额外调用；默认 Soft Harness 不产生额外模型请求。

## 为什么会慢

用统一时间轴区分：

1. 排队；
2. 模型首 token 等待；
3. 模型生成；
4. 工具执行；
5. 等待用户；
6. 结果整理；
7. Renderer 收到并绘制结果。

当前历史兜底轮询约 1.5 秒一次，可能让最终呈现最多晚一个轮询周期，但它不调用模型。下一步应采用实时事件优先、逐渐退避的轮询兜底。截图中的 6 分 6 秒包含 5 分钟等待用户超时，因此不能把总时长全部归因于回复生成。

## Hard Harness 与小体量 Soft Harness

Hard Harness 负责真正的执行循环：上下文装配、模型请求、工具调度、沙箱、审批、取消和持久化。它的主要费用来自模型推理、反复携带上下文，以及工具结果触发的后续模型轮次；本地状态机本身不是主要 token 成本。

Soft Harness 不复制这套循环。它是一个小而确定的适配层：

`Harness 事件 -> 规范化事实 -> Conversation / Run / Outcome / Recovery / Usage 投影 -> 人类界面`

默认所有翻译都由本地规则完成，新增模型调用数为零。只有用户明确请求“用模型解释复杂证据”时，才创建一个可见、可停止、可计费的普通任务。这样可以保持小体量，也避免第二个 Agent 偷偷改写第一个 Agent 的真实状态。

## 借鉴 Codex 插件生态的边界

采用其信息架构，而不复制其服务端目录：

- 统一目录按官方 / 精选 / 社区 / 已安装分面；
- 一个插件可由 Skill、MCP 工具和 UI 能力组成，也允许只包含最小的一种能力；
- 安装前展示来源、固定 commit、权限、构建步骤和作用域；
- 补齐已安装列表、禁用、卸载、升级、重启生效验证与失败回滚；
- DSH Bundle 仍通过官方 profile seam 安装，普通 GitHub 仓库不能伪装成插件。

Codex 的公共目录和分发后端不是 Deep code 可以直接复用的开源基础设施。Deep code 应当借鉴“统一包契约 + 能力分面 + 安装后管理”，并继续服从 DeepSeek Harness 的 Bundle 契约。

## 验收顺序

1. Decision Gate、停止、Recovery 的全量回归与测试版验证。
2. Adapter 增加可靠 Turn / Step 边界，落地过程折叠。
3. 把本轮状态移到可折叠右侧检查器，完成窄屏抽屉。
4. 调查并接入 Harness 原生 usage 事实；没有数据时保持未知。
5. 补齐已安装插件管理和失败回滚。
6. 最后再做玻璃风格、动效、图标和精细视觉统一。
