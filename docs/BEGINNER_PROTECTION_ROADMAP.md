# Deep code 新手保护层路线图

本路线图把 CodeWhale 工程建议中的教程摩擦翻译为可见产品模块。原则是：Deep code 负责发现、呈现、控制、解释、恢复和组合；DeepSeek Harness 继续拥有 Session、工具、权限、审批、模型、Skill 与执行真相。

## 交互骨架

每个状态模块都回答四个问题：

1. 现在是什么状态？
2. 这对当前任务意味着什么？
3. 用户下一步可以做什么？
4. 哪些技术证据可以展开核对？

首页始终只突出任务与对话。环境、模型和权限用一条紧凑的上下文栏常驻；只有发生阻塞时才展开恢复界面。

## P0：先让第一轮任务可靠发生

### 1. Engine 启动医生

可视化内容：Harness 来源与版本、Node 是否可用、依赖是否完整、端口状态、启动阶段和最后一次失败原因。

主要动作：自动检测、自动修复、重新启动、展开技术日志、导出脱敏诊断。

验收：从桌面启动的安装版不能依赖开发终端额外提供的 PATH；退出代码必须被翻译为“缺什么、为什么、怎么修”。

### 2. Workspace Guard

可视化内容：当前工作区的完整路径、来源（新建或已有）、是否存在、是否由 Deep code 初始化、起步文件、最近使用状态。

主要动作：新建、选择已有目录、打开文件夹、重新连接、切换项目。

保护边界：工作区是任务工作起点，不暗示突破 Harness 权限；不覆盖来源不明的同名目录。

验收：用户确认创建后，界面显示真实落盘路径和文件清单；重复选择 Deep code 自己创建的目录不会被误报成失败。

### 3. 首次运行路径

六个连续步骤：欢迎 → Engine 检测/修复 → 模型连接 → 工作区 → 当前权限说明 → 第一条示例任务。

每一步必须有进行中、成功、失败和恢复动作。用户不需要打开终端、理解 Node、端口或 `cd`。

### 4. 模型连接

默认界面只显示 Provider、连接状态和“验证连接”。API Key 交给 Harness 支持的配置/凭据机制，Deep code 不另造明文密钥仓库。

错误翻译至少覆盖：凭据无效、Provider/Endpoint 不匹配、网络不可达、模型不可用。技术响应放在折叠证据中。

已落地的纵向切片：读取 Provider、模型目录和凭据是否存在；通过 Harness 官方 Credentials seam 写入或清除固定的 DeepSeek 凭据；输入框始终为空且不回显旧值；把“已保存”与“已完成真实模型调用”分开呈现。真实验证会先说明可能消耗少量 token，再创建用户看得见、可追踪、可取消的普通任务，不使用隐藏 ping。

仍待补齐：把真实任务返回的认证失败、网络失败、模型不可用和限流错误稳定归类，并在首次运行向导中提供相同的恢复动作。

## P1：把 Engine 的真实状态翻译给人

### 5. 任务上下文栏

在任务顶部常驻：当前工作区、真实 Mode、Model/Route 摘要、真实 Permission preset、Engine 状态。默认显示人类语言，展开后显示 Harness 原值和来源。

### 6. Agent Activity 时间线

只映射 Harness 真实事件：正在读文件、正在修改、正在运行命令、正在调用工具、等待用户决定、已完成、已失败。不得根据生成文本猜测思维过程。

每条事件可以展开证据，但默认不向新手倾倒原始 JSON。

已落地的纵向切片：通过官方 mux WebSocket 接收当前任务的实时 turn、assistant message 和 tool 事件，显示最近活动；只把 `assistant/chunk` 中的 `text-delta` 作为“尚未定稿”的回答预览，明确丢弃 reasoning/analysis；断线后以 Harness 的持久历史重新收敛。工具展示优先采用 Harness presenter 生成读文件、写文件、Shell 与网络操作的影响摘要。

### 7. Decision Gate

把 Harness 原生审批或用户问题翻译为：将做什么、会影响哪里、主要风险、允许/拒绝后的结果。Deep code 只转译和转发，不代替 Harness 批准，也不从角色卡继承权限。

已落地的纵向切片：支持 `approval/requested` 的“只允许这一次/拒绝”，支持普通问题、多选问题、自由回答和带 intent 的计划审阅；响应只经官方 `/api/respond` 返回。断线时立即清除本地暂存 Gate，重连后只接受 Harness 重放的仍待处理请求，避免向过期审批作答。

### 8. Plan 影响预览

使用 Harness 真实规划能力展示预计影响：可能修改的文件、可能运行的命令、依赖变化和仍需用户决定的事项。用户可以继续讨论计划或进入执行，但 Deep code 不创造第二套 Plan 状态机。

## P2：让失败可以由普通用户恢复

### 9. 统一错误卡

统一结构：发生什么 → 为什么 → 怎么修 → 是否可重试 → 技术细节。错误代码至少覆盖 Engine 缺失/版本不兼容、Node/依赖缺失、端口占用、凭据、网络、工作区访问、插件与 Skill 激活失败。

### 10. 恢复中心

聚合最近失败、自动修复结果、重启 Engine、重新检测环境、重新选择工作区、导出脱敏诊断。诊断包明确列出排除项：密钥、聊天正文、工作区文件和 Harness Session 内容。

### 11. 任务完成与验证卡

任务结束时用人话说明：改了什么、用什么证据验证、哪些没有验证、当前风险和需要项目所有者做的决定。重要文件可以在 Evidence Drawer 中定位。

已落地的第一条纵向切片：只依据 Engine 终态和 Conversation Projection 已确认的事实，显示文件改动、明确的 test/check/lint/build 命令、失败操作和缺少验证的提醒；不从 Agent 回答中的自我评价推断成功。所有摘要都可回到 Run Details 核对。仍待补齐：Harness 原生 usage、结构化测试结果、项目所有者决定以及跨多轮的“本轮/全任务”范围区分。

## P3：生态入口，而不是新的权限系统

### 12. Skill / Plugin Library

显示来源、许可、安装范围（项目或全局）、版本、真实激活状态、声明能力与所需权限。安装前预览文件和目标位置，支持可逆卸载；成功状态必须由真实 Harness 集成测试确认。

Skill 与 Plugin 必须分开呈现：标准 `SKILL.md` 是按需加载的任务说明；Harness bundle 是会进入运行时的可执行代码与配置层。从 Git 安装 bundle 可能触发沙箱外的 `prepare` 构建，必须显示固定 commit、安装脚本授权、最终 `--dump-config` 差异和回滚点，不能伪装成普通角色卡下载。

### 13. Provider / Model 高级视图

默认只显示“自动/已连接”；展开后区分 Provider、Model、Route 与 Reasoning，并保留 Harness 的真实名称和值。Deep code 不把 Auto 伪装成具体模型。

### 14. 图片说明与静默问题录制

第一条纵向切片已落地：用户显式选择 PNG/JPEG/WebP/GIF，在当前 Task 下本机预览；未发送草稿只存在主进程内存中，不记录源路径。发送时才通过 Harness 官方 `session.prompt` 图片 seam；成功后清除草稿，失败时保留以便移除或重试。会话历史显示 Harness 已持久化的图片名称、尺寸和大小，不把 base64 暴露给 Renderer。

仍待补齐：剪贴板截图、模型图像能力的发送前检查、原图查看、短录屏本地抽帧与逐帧确认。录屏默认无麦克风、不实时上传，视频本体不进入模型上下文。

### 15. 生态发现（默认关闭、只读）

第一条纵向切片已落地：用户开启后才读取 GitHub 官方发现约定所使用的 `dsh-plugin` topic 元数据；按 Stars 展示社区热度，但每张卡明确说明未做安全审计、兼容性测试、固定 commit 或 Bundle 验证。只提供“查看上游源代码”，没有安装、运行、激活或修改 Harness profile 的入口；关闭状态不发网络请求，也不启动 Engine 或调用模型。

仍待补齐：经过人工复核的固定 commit 快照、Bundle manifest 静态证据、Windows/DSH 版本兼容记录、来源适配器和可解释筛选。安装能力必须作为另一个需要备份与 diff 预览的高风险功能单独设计。

## P4：角色、协作与河床

角色模块不得阻塞 P0-P2。它采用两层结构：

- 可移植层：标准 Agent Skill（至少包含 `SKILL.md`），并兼容 DSH 的项目级或全局 Skill 发现；
- Deep code 层：独立 `deep-code.role.json` sidecar，记录河床、来源、纠正、版本与分享范围，不污染上游 Skill schema。

“河床深度”增加的是稳定价值与取舍、关系动力、冲突后的恢复轨迹、观察/推断/用户纠正、置信度、时间性和情境范围，而不是口癖数量。任何 Persona、角色或河床都不能提升 Shell、工具、网络、工作区或审批权限。

阶段顺序：只读发现与风险检查 → 项目级可逆安装和真实 DSH 激活 → dot-skill 元数据增强 → 河床 sidecar 与版本回滚 → 导入导出。

## 发布闸门

发布只交付已经具备真实复现和验证闭环的纵向切片，不再按 P0/P1 编号机械阻止已经成熟的后续模块。每个进入发布的可视化模块都必须同时具备：正常状态、进行中、可恢复错误、技术证据折叠、自动化回归测试和 Windows 安装版实测；没有真实 Harness 数据源的多代理成员、成本或 usage 面板不得以占位数据进入产品。
