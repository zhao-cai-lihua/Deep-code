# Deep code v0.6.3-rc.5

这是 v0.6.3 安全与证据边界的第五个测试候选，尚不是稳定版。它来自一次覆盖 `v0.6.2` 到 rc.4 全部改动的最终复核，修复了四个会让界面展示错误任务或错误运行结论的竞态与证据关联问题。

## 本次修复

- 每次 Prompt 都保留其 JSON-RPC 请求 id，并只接纳 durable history 中 `user/message.source.rpcId` 相同的 Turn。新任务不会再短暂继承旧一轮的模型、工具、文件变化或“已完成”。
- 点击任务、新建任务和切换工作区统一经过 generation、taskId、sessionId 三重校验。迟到的旧结果不能覆盖当前工作台。
- 发送消息在异步模型准备完成后、真正调用 `session.prompt` 前再次确认目标任务与 Session，降低“看着 B，发到 A”的风险。
- 五分钟无人回答时，Deep Code 只会说明已向 Harness 发送停止请求；只有匹配的终态事件才能证明本轮确实停止。

## 未改变的边界

- Harness 仍是 Session、模型、工具、权限和执行状态的唯一真相。
- Provider 凭据、模型路由和已验收的 Engine Trust 行为没有改变。
- 生态发现仍可浏览，但没有可执行安装路径。
- 没有增加自动模型路由、Memory Prompt 注入或角色卡注入。
