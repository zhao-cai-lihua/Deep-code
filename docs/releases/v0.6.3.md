# Deep code v0.6.3

v0.6.3 是 Deep Code 的安全与证据稳定版。它保留官方 DeepSeek Harness 作为 Session、模型、工具、权限与执行状态的唯一真相，并把桌面端收紧为经过验证的连接、投影、解释、恢复与可视化层。

## 给普通用户的变化

- 托管 Engine 由 Deep Code 自己启动、使用系统分配的回环端口，并在可用前核对固定 Harness runtime；其他占用 3080 端口的服务不会被自动当成 Harness。
- 外部共享 Harness 必须先通过兼容性检查，再由用户明确确认；确认前不能发送任务、写入模型凭据或恢复执行。
- 托管 Engine 不再继承桌面进程中的未知 API Key、Token、Secret、Password、Credential 或 `NODE_OPTIONS`。
- 本地任务采用可回退的版本化快照；第二个 Deep Code 实例只聚焦已有窗口，不再成为第二个任务文件写入者。
- 工作回执只把同一 Session、同一轮结构化事件证明的内容说成事实。请求已接收、开始运行、终态、模型路由、权限、工具成功、文件变化和验证结果不再混为一谈。
- 运行中的任务使用“停止并删除”：先请求 Harness 停止，只有匹配终态确认后才删除本地记录；无法确认时保留控制信息和恢复入口。
- 快速切换任务、异步刷新和发送前目标复核都受任务与 Session 身份保护，避免“看着 B、实际写到 A”。
- 每个任务和空白“新任务”界面都有独立的未发送文字草稿；切换任务不会串线，成功发送只清除当前草稿。
- Memory Vault 会重新验证 ID、路径和目录状态，隔离畸形记录并拒绝高可信秘密材料；Memory 仍不会自动注入 Agent Prompt。
- 生态发现继续提供中文简介、星标和源码链接，但可执行安装保持暂停。高星项目不会被冒充成已验证 Harness 插件。

## 兼容性与边界

- 当前只自动信任官方 Harness `dsh-v0.1.1-rc.2`，根版本 `0.1.1-rc.2`，Git commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`。
- 上游 `host.describe.version` 在该提交中仍返回占位标记 `0.0.1`；Deep Code 将它作为固定提交的兼容标记，而不是向用户展示的发行版本。
- Deep Code 不检查、推断或回显 API Key 内容。凭据已保存、Provider 已启用、模型出现在目录中和某次真实请求曾验证通过，仍是四种不同事实。
- 未发送草稿只在当前 App 进程内保存，退出 App 后不承诺恢复。
- 当前没有商业代码签名证书。请从本 Release 下载，并用随附的 `SHA256SUMS.txt` 核对文件。

## 验证证据

- 全量 `npm test`：259 项通过。
- Windows 测试打包：通过；已检查打包后的 `app.asar` 包含接受候选的草稿隔离、Evidence Gate、Outcome 与 Recovery 投影。
- 人工验收覆盖托管 Engine、敌意 3080、真实共享 Harness、单实例、Provider/模型连接回执、任务/工作区切换、Memory 生命周期与检索预览、模型弹窗焦点恢复、任务草稿隔离。
- 稳定版不包含相对于已验收 rc.6 的运行时改动；版本与发布资料单独经过完整测试和打包。
