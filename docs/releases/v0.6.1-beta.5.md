# Deep code v0.6.1-beta.5 engineering checkpoint

This checkpoint collects the post-v0.6.0 beginner-workbench work before the next packaged beta. It is a source checkpoint, not a published installer release.

## What is real in this checkpoint

- Conversation and Trace are separate views over the same Harness evidence. Tool activity no longer fragments the readable answer.
- Decision Gates remain interactive at the latest edge of their own task, refresh the five-minute idle window while the user is active, and leave a recovery explanation when the wait expires.
- A running task exposes a stop action through the official Harness cancel path.
- New tasks, disclosure state, image drafts, and recovery state stay isolated by task.
- The fixed sidebar holds workspace creation/selection and a compact Harness-backed run summary while the conversation scrolls.
- The composer can explicitly select only models and reasoning efforts advertised by the current Harness Session. No selection preserves the Harness route; Deep code does not perform automatic task-role routing.
- The Model Connection panel can add a reviewed simple API-key provider only when current Harness settings are writable. Provider profile creation and write-only credential storage are separate stages, and partial failure is reported honestly.
- Ecosystem discovery remains opt-in. Installation requires a commit-pinned GitHub repository with a root `dsh.bundle.patch`, a second confirmation, and the official DSH CLI/profile path.
- The unapplied Companion Card and Reply Mode experiment is absent from the product and runtime bridge. Existing local drafts are not deleted.
- Terminal outcome, confirmed file changes, explicit verification, warnings, recovery, and the visual Work Receipt all derive from Harness-backed evidence rather than assistant self-report.

## Verification recorded for the checkpoint

- `node --check` passes for changed and new JavaScript/CommonJS files.
- `npm test` passes 137 tests.
- `git diff --check` reports no whitespace errors.
- A secret-pattern audit found no candidate credential committed by this checkpoint.

## Not yet claimed

- This checkpoint has not completed a packaged Electron smoke test.
- Custom OpenAI-compatible endpoints and OAuth provider setup are not implemented.
- Harness does not yet provide authoritative usage/cost data through the current Deep Code Adapter.
- The plugin flow still lacks an installed-list, uninstall, and verified profile rollback experience.
- No Setup or Portable executable is published from this checkpoint.
