# Deep code v0.6.1-rc.3 engineering checkpoint

This release candidate contains one post-rc.2 structural hardening change. It does not add a new product feature or alter Harness authority.

## What changed

- The add-Provider second-click confirmation is now owned by a focused Renderer state module rather than ad-hoc state inside `shell.js`.
- The flow accepts only the selected Provider identity. It never receives, stores, compares, or infers from the API Key.
- Changing Provider, editing the Key, reaching the ten-second deadline, or explicitly resetting the dialog invalidates the pending confirmation.
- Renderer contract tests now verify the module boundary instead of requiring safety copy to remain embedded in the orchestration file.

- Focused Provider-flow and Renderer-contract tests pass.

- Electron read the packaged `app.asar` and confirmed the new state module plus the updated `index.html` and `shell.js` are present. The unpacked packaged app remained running for an eight-second isolated-profile startup smoke test.

## Release boundary

- Saving a credential still proves only that Harness accepted the write. It does not prove provider identity or connectivity.
- A real visible verification task remains required for model-call evidence.
- No automatic model routing, memory injection, relationship prompt, or second execution state is introduced.
- This checkpoint is not a GitHub release until its packaged artifact is accepted and the formal release operation is explicitly authorized.
