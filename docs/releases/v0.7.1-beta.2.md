# Deep code v0.7.1-beta.2

这是 Soft Harness 的第二个测试版。beta.1 的协作约定虽然存在，但砚星实际使用后反馈“变化并不明显”。这一版不靠增加另一个 Agent Loop 来制造存在感，而是把协作方式和 Harness 已经证明的执行事实连成一条可见路线：**对齐目标 → 推进任务 → 核验结果 → 交付回执**。

## 这次会明显在哪里

- 新任务输入框的开关改为“协作：清晰推进”。关闭后仍可原样发送。
- 新版一次性协议要求 Agent 首次可见回复先用一至三点说明“我理解的任务”，然后直接行动；简单任务可以只用一句话。
- 只有真正影响结果或风险的关键问题才暂停，并尽量提供二至三个可执行选项与建议。
- 过程中只在有意义的阶段变化、需要决定或遇到阻碍时用普通话更新，不把系统提示、原始思维链或逐条工具日志当作用户回复。
- 最终回复先给结果，再说明实际改动、实际验证、仍未确认和安全恢复方式。
- 对话上方新增四阶段“任务路线”。点击“对齐目标”可看任务说明；点击“推进任务”或“核验结果”可看轨迹；点击“交付回执”可看结果与证据。

## 任务路线怎样保持诚实

任务路线不是第二套执行状态机。它只投影当前任务已经存在的 Task Contract、Harness admission/Turn、结构化运行状态和工作回执：

- `session.prompt` 只证明请求被接纳。在 Session 历史尚未出现带协议的用户消息前，“对齐目标”只显示进行中，不会提前变绿。
- “推进任务”只跟随现有 Harness 运行投影；等待用户、失败与停止均保持需要留意。
- “核验结果”只根据现有验证与文件变化证据着色。任务完成不自动等于测试通过。
- “交付回执”在仍有警告、风险、失败或未知验证时保持黄色，不制造肯定结论。
- 四张阶段卡只负责导航；不能发送消息、授予权限、选择模型或改变 Session。

## 兼容性与成本

- 新创建的引导任务使用 Task Contract v2；beta.1 已创建的 v1 任务仍可解析、显示和重试，不会被静默改写。
- v1 一次增加 380 个字符；v2 一次增加 622 个字符。它们只出现在新任务首条文字消息，后续消息不重复。
- 任务路线完全由本地投影生成，不增加模型调用，也不增加 Provider API 费用。
- 图片-only、旧任务、模型连接验证、Project Brief 和“原样发送”任务保持原行为。
- DeepSeek Harness 仍是 Session、模型、工具、权限、执行状态和证据的唯一真相。

## 砚星的低成本验收

1. 新建任务时确认开关显示“协作：清晰推进”，并且可以切换成“协作：原样发送”。
2. 借用一次原本就要做的日常任务发送。确认对话上方出现四阶段路线，并观察首次回复是否先说明“我理解的任务”再行动。
3. 在同一任务继续发一句话，确认第二条消息不会再次附加协议。
4. 分别点击四张阶段卡：应打开任务说明、轨迹或回执，不会触发新的执行。
5. 若自然遇到“改了文件但没有验证”的任务，确认“核验结果”和“交付回执”保持黄色。不要为了这一项专门消耗 Provider token。

这是行为与体验候选，不是稳定版。若 Agent 仍未明显遵循首条对齐、阶段更新或结果优先，请记录一次自然任务的表现；无需反复付费测试。
