# Deep code v0.7.1-beta.1

这是第一个可实际感知的 Soft Harness 小实验：**新手任务契约**。它不增加新的 Agent Loop，也不新增模型调用；它只在新任务的首条文字消息后，公开附上一份简短、可审阅、可关闭的协作约定。

## 它解决什么

普通用户往往只知道自己想要什么，不知道哪些工程细节必须提前写进 Prompt。默认的“可核验推进”约定会请当前 Agent：

- 只有关键前提缺失、且不同选择会实质改变结果或风险时，才提出尽量少的问题并等待决定；
- 能够安全推进时直接行动，保留已有工作，不静默扩大范围，不把推断写成事实；
- 交付时区分已确认与未确认，说明实际验证和可用恢复方式。

这不是权限系统。它不会改变 Harness 的模型、工具、权限、工作区或批准策略，也不证明任务已经完成；所有执行事实仍以 Harness 结构化事件为准。

## 用户能看见什么

- 新任务输入框旁新增“协作：可核验”。点击后可改为“协作：原样发送”。
- 约定只附加在新任务的首条文字消息；后续追问不会重复占用上下文。
- 当前版本精确增加 380 个字符，不估算模型 token 或金额，也不会触发第二次模型请求。
- 对话仍以用户原话为正文；约定收在“协作约定 · 可核验推进”的折叠条目里。
- “查看任务说明”会列出原始任务、约定正文、字符开销和权限边界。
- 旧任务、图片-only 任务和选择“原样发送”的新任务保持原行为。

## 安全与兼容性

- Task Contract 作为版本化字段保存到本地任务记录，旧版本任务库会安全迁移；旧任务默认没有约定。
- 只有正文与请求哈希都完整匹配的约定才会在对话中折叠。被修改或形似约定的普通用户文字会原样显示；这里是完整性校验，不宣称密码学身份认证。
- 模型连接验证、Project Brief、继续消息、Provider、Memory、生态发现与模型路由不接入这份约定。
- DeepSeek Harness 继续是 Session、模型、工具、权限和终态的唯一真相。

## 砚星的低成本验收

1. 点击“新任务”，确认输入框旁有“协作：可核验”，点击后能切换成“协作：原样发送”，再切回。
2. 保持“可核验”，发送一个日常小任务。确认你的消息正文仍只显示原话，下方多出一个默认收起的“协作约定”条目。
3. 打开“查看任务说明”，确认能看到约定内容、只附首条、增加 380 个字符，以及“不改变 Harness 权限”的说明。
4. 在同一任务继续发送一句话，确认第二条用户消息下方没有重复出现协作约定。

第 1 项不调用模型；第 2～4 项可利用一次原本就要做的日常任务完成，不必专门创建高成本测试。若不喜欢这套约定，可以在发送新任务前选择“原样发送”。
