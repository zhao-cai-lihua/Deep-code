# Deep code v0.6.3-rc.4

这是 v0.6.3 安全与证据边界的第四个测试候选，尚不是稳定版。它继承 rc.3 的模型验证历史修复，并收紧共享 Engine 在确认瞬间发生变化时的恢复状态。

## 本次修复

- 共享 Harness 在确认前会重新验证固定 runtime、`host.describe`、版本标记和工作目录。
- 重新验证失败时，旧候选立即失效，状态从“等待你确认”切换为“版本不兼容”，不再留下一个看似还能继续使用的失效确认入口。
- 失败说明会要求重新启动 Engine 检查，再确认新的实例；再次点击旧确认会被拒绝。
- 模型连接区域的用户可见文案从大型 `shell.js` 中抽成独立、可行为测试的投影。测试现在验证“凭据已保存”和“最近一次真实验证通过”确实会同时呈现，而不只是验证源码里存在这些文字。

## 零模型费用的真实协议验收

本机固定官方 Harness checkout 完成了两组真实启动检查：

- 真实共享 Harness：确认前停在 `awaiting-user` 且不能被任务使用；明确确认后绑定 `user-confirmed-shared`、精确 URL、版本和工作目录；Deep Code 不会停止自己不拥有的共享进程。
- 假 3080 服务：一个对任意请求返回 HTTP 200 的普通服务没有被识别为 Harness；Deep Code 改在随机回环端口启动并验证自己的托管 Engine，随后正常停止。

打包后的 rc.3 还使用隔离用户目录进行了双启动：第二个启动器退出，仍只有一个主进程，证明单实例写入者行为在打包环境中成立。所有测试进程均已停止，3080 已恢复空闲。

这些检查没有创建 Harness Session、没有发送 Prompt、没有读取或写入 API Key，也没有消耗 Provider token。
