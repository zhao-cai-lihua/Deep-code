# Deep code v0.6.3-rc.2

这是 v0.6.3 安全与证据边界的第二个测试候选，尚不是稳定版。请使用低价值测试 Key、非敏感工作区和已有备份完成验收。

## 相比 rc.1 的关键修复

rc.1 会拒绝正确的官方固定 runtime，错误提示为：

> Engine 报告版本 0.0.1，与已验证 runtime 0.1.1-rc.2 不一致。

原因不是安装错误。固定的上游提交在 `host.describe.version` 中硬编码了占位值 `0.0.1`，源码也明确留下了“以后读取 CLI package.json”的 TODO。这个字段不是 Harness 的 `0.1.1-rc.2` 发行版本，也不是独立发布的协议版本。

rc.2 将证据明确拆开：

- runtime 身份由官方根包名、tag `dsh-v0.1.1-rc.2`、package 版本 `0.1.1-rc.2` 和精确 Git SHA `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e` 共同验证；
- `host.describe.version: 0.0.1` 只作为这个固定提交的内部 Host 兼容标记；
- Engine 的规范化工作目录仍必须与被验证的 runtime 一致；
- 托管 Engine 仍必须是 Deep Code 自己启动并持有的随机端口子进程；
- 用户界面和任务证据显示真正的 runtime 版本 `0.1.1-rc.2`，不会把 `0.0.1` 冒充发行版本。

因此 Trust Gate 没有被关闭或放宽，只是修正了两个不同版本概念之间的错误比较。

## 继承的安全边界

- 外部共享 Engine 仍需逐实例明确确认；确认前不能发送 Prompt、写入 Provider 凭据或恢复任务执行。
- 托管 Engine 使用随机回环端口和清理后的子进程环境。
- 自动 runtime 安装固定到官方 tag 与 SHA，不跟随可变默认分支。
- 生态发现只读，产品中没有可到达的安装路径。
- Memory、任务快照、Evidence Gate、停止并删除、异步任务切换门禁均保留 rc.1 的安全实现。

## 验证状态

- Engine Trust 与 Runtime Supervisor 聚焦测试：16 项通过。
- 全量 `npm test`：244 项通过。
- 对本机精确固定的官方 Harness 做了无模型真实启动：进入 `managed-process / ready`，对外显示 `0.1.1-rc.2`，内部标记 `0.0.1`，随后正常停止。
- 此检查没有创建 Session、没有调用 Provider，也没有消耗模型 token。

Windows 打包、发布资产校验和砚星的人工验收将在候选发布后记录。只有安全矩阵通过，才会发布 v0.6.3 stable。
