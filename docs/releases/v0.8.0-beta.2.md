# Deep code v0.8.0-beta.2

This is the corrected local test candidate for the Guided Workbench milestone. It is not a stable release and must not replace v0.7.0 until the bounded manual checks below pass.

## Correction from beta.1

- Removed every Deep code path that sent `/plan` or `/plan off` through `session.prompt`.
- Direct now performs no hidden collaboration-mode request before the user's real task.
- The pinned `dsh-v0.1.1-rc.2` Web client has an in-process command plane, but its remote API Proxy does not expose that plane. The Deep code Plan selector is therefore disabled and explains the compatibility boundary.
- Existing structured Harness Plan projections remain readable in the right inspector. Deep code does not create a second local Plan state.
- A forged or stale Plan selection fails before the real task is sent. A Session that Harness has already placed in Plan can still be represented from structured evidence, but Deep code does not claim it can remotely toggle that state.

## Guided Workbench retained

- One continuous center conversation with a foldable right inspector for Harness phase, structured Plan/Todos, model route, Session usage, activity, and outcome.
- Strict same-Session, higher-sequence projection validation; bounded paged history; task/Session/generation race guards; and transition-based privacy-safe notifications.
- No local Planner, Agent Loop, completion authority, model-cost estimate, plugin execution, automatic Memory injection, or companion-card prompt.

## Bounded manual acceptance

Only check the correction and the surfaces most likely to regress. One low-cost Direct task is sufficient.

1. Open a new task. The mode control must show `Direct` and be visibly unavailable; it must not offer a clickable Plan toggle.
2. Type a distinctive natural-language sentence and send it. The conversation must contain that sentence once, must not contain a separate `/plan` or `/plan off` user bubble, and must receive a normal answer.
3. Switch between two tasks while one has an unsent draft. Draft, inspector, history, dialog, and activity state must remain task-scoped.
4. Resize below the three-column breakpoint and confirm the right inspector folds and reopens without changing task state.
5. If a historical Session naturally contains a structured Harness Plan projection, Deep code may label it `Plan (Harness)` and show its Todos, but the mode control remains unavailable.

## Boundary for restoring Plan switching

Plan switching may return only after a supported Harness runtime exposes a remotely callable command-plane method, Deep code pins and validates that runtime, and behavior tests prove that a bare Plan selection produces command lifecycle evidence without a model-visible user message or Provider token request.
