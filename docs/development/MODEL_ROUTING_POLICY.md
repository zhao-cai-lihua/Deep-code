# Deep Code 开发协作的模型路由规则

状态：2026-08-23 起试行。它约束砚星与林开发 Deep Code 时怎样分配模型，不是角色卡，也不改变 Harness 的模型、工具、Shell、Sandbox 或批准策略。

## 目标

在不牺牲正确性、隐私和可验证性的前提下，减少昂贵模型处理机械工作所消耗的额度。多代理不被当作默认加速器：它可能减少等待时间，却会增加上下文复制、协调和汇总的总 token。

## 默认路线

| 任务形状 | 默认模型 | 理由 |
| --- | --- | --- |
| 目标澄清、产品取舍、架构 seam、安全与权限、陌生协议、失败诊断、最终验收 | Sol | 这些步骤的错误会改变方向或扩大风险，需要旗舰判断。 |
| 已有清晰规格的普通功能实现、局部重构、跨几个文件的可测试改动 | Terra | 在质量、速度和成本间取平衡。 |
| 固定来源清单、机械检索、格式化、测试夹具、重复性改写、边界明确的文档整理 | Luna | 输出可快速核验，适合低成本高吞吐执行。 |

## 调度约束

1. 默认只运行主代理，不为了“可能更快”而并行。
2. 普通任务最多下放一个有界子任务；只有两个工作流真正独立且能并行验收时才增加第二个。
3. 每个下放任务必须写明输入范围、允许修改的文件、禁止动作、输出位置和验收命令。
4. 子代理不得自行提交、推送、发布、改权限、接入密钥或扩大任务范围。
5. 研究结果必须落到仓库文档并保留一手来源；主代理只核对结论和产品取舍，不重复整份阅读。
6. 失败诊断、真实用户数据、凭据、付费调用和破坏性操作不因使用便宜模型而降低审查级别。
7. 如果委派后的协调成本接近直接完成，就停止委派并回到单代理。

## 一次工作的标准形状

```text
Sol：确定目标、风险、验收标准和可下放边界
  ↓（只有边界清楚时）
Terra 或 Luna：实现 / 检索 / 生成固定交付物
  ↓
Sol：读取差异与证据，运行关键验收，决定是否接受
```

“Sol 规划、Luna 执行”不是硬编码。小 bug 可以由一个模型直接完成；复杂但规格清楚的实现更适合 Terra；需要持续语义判断的工作不应切成廉价流水线。

## 怎样判断是否真的省额度

对有代表性的任务记录以下指标，再决定是否扩大使用：

- 任务是否一次通过验收；
- 主代理是否不得不重做子代理工作；
- 总输入/输出 token（宿主能提供时）；
- 高价模型 token 占比；
- 墙钟时间；
- 工具调用和重试次数；
- 是否遗漏证据、权限边界或用户要求。

只有在质量不下降时，较低成本、较少旗舰 token 或更短等待才算改进。

## Deep Code 产品内的未来模型路由

Deep Code 可以在 Harness 官方模型与 LLM adapter 生态之上增加“人类可理解的路由策略”，但不能另造第二个 Agent Loop。产品层只负责：

- 显示本轮实际使用的 Provider、Model、推断强度和可获得的成本信息；
- 让用户选择“质量优先 / 平衡 / 节省”，并在发送前预览实际映射；
- 将每次路由作为会话证据保存，失败时显示是否回退以及回退原因；
- 对付费、跨厂商或会把内容发往新服务的回退进行明确确认；
- 把模型选择与角色卡彻底分开，角色卡永远不能修改 Provider、Model 或计费策略。

Deep Code 不应：

- 悄悄把完整项目或会话发送给另一个厂商；
- 让模型自己在无限候选中循环尝试；
- 因为便宜而降低 Sandbox、Approval 或工具权限；
- 在 Renderer、本地任务 JSON、日志或角色卡中保存 API Key；
- 在没有同任务评测前宣称自动路由一定更省钱或更聪明。

## 外部厂商 API 的接入门槛

砚星暂时不需要提供任何密钥。接入某个厂商前必须先完成：

1. 固定其官方 API 与许可/隐私来源；
2. 明确哪些工作内容会离开本机；
3. 通过 Harness 官方 adapter 或独立、受审计的 adapter 接入；
4. 使用 write-only 凭据 seam，不让 Renderer 读取旧值；
5. 提供连通性测试、模型目录、限额、超时、重试和显式回退；
6. 用同一组 Deep Code 任务比较质量、延迟、总 token 和成本；
7. 由用户明确开启，不作为角色卡或首次向导的隐式步骤。

## 当前试验记录

- 2026-08-23：主代理负责新任务状态 bug 的复现、修复与验收；Luna 仅负责 DeepSeek Harness / Codex 官方一手来源研究并写入固定报告。此试验不涉及外部 API Key、产品运行时路由、提交或发布。

## 官方依据

- OpenAI Model guidance：Sol 是旗舰能力路线，Terra 平衡能力与成本，Luna 面向高吞吐高效率；模型与 reasoning effort 应针对代表性任务比较，而非默认越高越好。https://developers.openai.com/api/docs/guides/latest-model
- OpenAI Model guidance：Multi-agent 适合可以干净拆成独立工作流的复杂任务，主要收益之一是墙钟时间；最终仍应比较质量、tokens、延迟和成本。https://developers.openai.com/api/docs/guides/latest-model
- Codex open agent harness：应用拥有界面、产品上下文与业务控制；harness 负责 Agent Loop、会话、流式事件、工具和批准。https://developers.openai.com/blog/codex-as-a-platform
